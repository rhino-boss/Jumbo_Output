# Omniplay（Jumbo_Output）

工作成果的網頁索引站。線上位址：<https://rhino-boss.github.io/Jumbo_Output/>

> **來源路徑寫在 `assets/app.js` 最上面的 `SLOTS_PATH` / `ANALYSIS_PATH`。**
> Jumbo repo 若又改結構，改那兩行就好 —— 2026-09-08 該 repo 拿掉了
> `Project/` 這一層（`Project/Slots` → `Slots`），整站的內容一度全空。

## 檔案

```
index.html         首頁，分四區
all.html           完整頁，四區共用（?cat=demo|analysis|report|links）
catalog.js         手動收錄清單（其他報告、常用連結寫在這）
assets/style.css   兩頁共用樣式
assets/app.js      兩頁共用的資料載入與卡片渲染
assets/favicon.*   深藍底白 J
.nojekyll          讓 GitHub Pages 原樣輸出，不跑 Jekyll
```

## 首頁四區

| 區塊 | 色 | 來源 | 首頁呈現 | 上限 |
|---|---|---|---|---|
| Demogame | 藍 `#4a7fd0` | 自動掃描 `Slots/<代號_名稱>/index.html` | 遊戲卡橫向軌道，一次看 3 張、可左右滑動 | 4 |
| 競品分析 | 紅 `#d9534f` | 自動掃描 `競品分析/遊戲數據_*.html` | 卡片格 | 4 |
| 其他報告 | 琥珀 `#d9a13f` | `catalog.js` 的 `cat: "report"` | 卡片格 | 4 |
| 常用連結 | 綠 `#6b8f71` | `catalog.js` 的 `cat: "links"` | 連結列 | 6 |

版面沿用 **Cworld 爬山頁**的結構：最上方是狀態列（綠點＋一句總覽）、
四個統計方塊（各區筆數，頂端 3px 色條標分類），接著搜尋框，
再往下是四個區塊。區塊標題是純文字＋色點＋筆數，右側放操作。

顯示上限見上表（`index.html` 的 `LIMIT`，每區各自設定 —— 常用連結是一列一個的
連結列、比卡片矮，所以多放兩個仍不占版面）。要看全部走該區的「完整頁 →」，
首頁沒有就地展開的按鈕。區塊標題右側顯示的是**總數**，所以看得出來還有多少沒列出。
搜尋時不套上限 —— 使用者已經自己縮小範圍了，再砍掉只會擋路。

四個統計方塊是**橫向軌道**：容器夠寬就均分撐滿，塞不下時左右滑動
（`flex: 1 0 180px` ＋ `overflow-x: auto`），不再擠成兩列。

首頁的 Demogame **固定用遊戲卡**，沒有卡片／清單切換 —— 那個切換只在完整頁提供。

**四區都有「完整頁 →」**，連往 `all.html?cat=<分類>`。

搜尋一次過濾全部四區。

常用連結不用卡片，改用爬山頁「其他頁面」那種**連結列**
（分群標籤＋名稱＋→ 箭頭），一行一個、較省版面。

## Demogame

### 卡片內容

沿用 Cworld `studio/demogame` 的卡片：封面圖、NEW 緞帶、遊戲名＋版本號、
遊戲類型、底部兩顆按鈕。

- **封面** ← `Slots/其他/遊戲資源/<代號>.png`；沒有就只放 🎰 佔位
  （目前 H027、H028 沒有封面圖）
- **版本號** ← `Versions/version_manifest.js` 的 `current`；沒這個檔就留空
  （目前只有 H016、H027、H028 有）
- **遊戲類型** ← `game_rule.md`，正規化成
  `Cluster Pay / Pay Anywhere / N Ways / N Lines`（＋Cascade 等），
  邏輯與 Cworld 的 `normalizePlay` 相同
- **遊戲資訊** → GitHub 上的 `game_rule.md`（會渲染 markdown）；沒有規則書就停用
- **開始遊玩** → demo 頁，開新視窗；沒有 `index.html` 的遊戲顯示「製作中」

封面圖與版本檔**在不在都直接從 Slots 子樹判斷**（那棵樹本來就抓了），
不會先打再看 404 — 所以 console 乾淨，也不浪費請求。

### 排序與 NEW

依**文件日期**，最新的在前；同日的用代號遞增。文件日期取捨順序：

1. `修改紀錄.md` 最上面的 `## YYYY-MM-DD`（真正的最後更新，但不是每款都有 ——
   目前只有 H027、H028）
2. `game_rule.md` 的 `> 撰寫日期：YYYY-MM-DD`（每款都有，但只是初次撰寫日）

兩者都是同源的 Pages 靜態檔，**不吃 API 額度**。原本是用
`/commits?path=<資料夾>` 拿真正的 commit 時間，雖然精準但每款 1 次，
未登入額度每小時 60 次又依對外 IP 計算，全辦公室共用一個 IP 時
六個人各開一次就用完了。

兩款文件都找不到日期時該遊戲排在最後，並在提示區列出是哪幾款。
NEW 緞帶固定掛在最新的 3 款（在完整頁切換排序時也不變）。

### 橫向軌道

一次顯示 3 張（`flex: 0 0 calc((100% - 28px)/3)`），其餘左右滑動，
帶 `scroll-snap`。900px 以下 2 張、640px 以下 1 張。
首頁上限是 4 筆，所以第 4 張要滑一下才看得到。

## 完整頁 all.html

四個分類共用同一頁，用 `?cat=` 決定內容。每頁都有搜尋加三顆按鈕 ——

| 按鈕 | 行為 |
|---|---|
| `⇅ …` | 一顆按鈕，點一下切換該分類的兩個排序依據 |
| `↓` / `↑` | 切換升冪／降冪 |
| `☰ 清單` / `▦ 卡片` | 切換檢視模式 |

三者都是「點一下就切換」的同一種操作邏輯。排序與檢視模式**各分類獨立**
記在 `localStorage`（`omniplay-sort-<cat>`、`omniplay-view-<cat>`）。

**預設一律是「清單」檢視**（一列一筆、左側色條標分類）。預設排序刻意各自指定，
讓完整頁的順序與首頁看到的一致：

| 分類 | 兩個排序依據 | 預設 | 卡片檢視長相 |
|---|---|---|---|
| Demogame | 更新時間 / 代號 | 代號 ↓ | 遊戲卡（封面＋版本＋兩顆按鈕） |
| 競品分析 | 報告日期 / 名稱 | 報告日期 ↓ | 一般卡片格 |
| 其他報告 | 日期 / 名稱 | 日期 ↓ | 一般卡片格 |
| 常用連結 | 預設順序 / 名稱 | 預設順序 ↑ | 連結列 |

常用連結的「預設順序」就是 `catalog.js` 裡的順序 —— 若預設按名稱排，
那邊排好的順序就白排了。

排序同分時固定用標題遞增，切換方向時同分項目的順序才不會跟著顛倒。

## 競品分析

列出 `競品分析/` 的 `遊戲數據_*.html`（`索引.html` 不收），
再讀同資料夾的 **`README.md`** 解析兩張表格填卡片資訊：

- 表一「| 遊戲 | 廠商 | 付費轉 | 報告日期 | … | 報告 |」→ 標題、廠商、付費轉、日期
- 表二「| 指標 | <遊戲名>… |」的 `總 RTP` 與 `官方 RTP` → 說明裡的 RTP

官方 RTP 是 `⏳` 時自動省略該段。README 沒列到的檔案仍會上架，標題從檔名反推。

> **維護 `競品分析/README.md` 的表格，就等於維護這區的卡片內容。**

## API 用量

未登入的 GitHub API 限**每小時 60 次，而且依對外 IP 計算** —
辦公室共用一個 IP 時，是全辦公室一起分這 60 次。所以整站**只用 2 次**：

```
/git/trees/main:Slots?recursive=1   1   一次取回整棵 Slots 子樹
/contents/競品分析                   1   列出競品報告
```

一小時可承受約 30 人次冷啟動。其餘 13 次請求都是同源的 Pages 靜態檔、
不吃額度：7 份 `game_rule.md`、2 份 `修改紀錄.md`、3 份 `version_manifest.js`、
1 份競品分析 `README.md`。哪些檔案存在是直接從 Slots 子樹判斷的，
不會先打再看 404。

### 額度用完時的降級行為

`403`／`429` 會被單獨辨識為「額度用完」，並依情況降級，不會讓區塊無聲變空白：

| 情況 | 行為 |
|---|---|
| 只有 commits 打不通 | 遊戲照常顯示，排序改用 `game_rule.md` 的**撰寫日期**，並顯示提示 |
| 目錄也打不通、但有 24 小時內的快取 | 顯示上次掃到的清單，並說明是快取 |
| 目錄打不通且無快取 | 該區為空，但明確告知是額度問題、稍後重新整理即可 |

碰到第一次 `403` 後就不再打剩下的 commits（先探一款再平行抓其餘，
否則平行請求會讓旗標來不及生效）。
其他報告與常用連結是純靜態的，任何情況都正常顯示。

## 新增內容

- **Demogame**：在 Jumbo 專案建 `Slots/H0xx_名稱/index.html` 並 push
- **競品分析**：把報告放進 `競品分析/`、更新該資料夾的 `README.md` 表格
- **其他報告／常用連結**：編輯這裡的 `catalog.js`

```js
window.CATALOG = [
  {
    title: "某個常用網頁",
    url: "https://example.com/",   // 完整外部網址，或站內相對路徑
    cat: "links",                  // demo | analysis | report | links
    game: "PG",                    // 選填
    desc: "一行說明",               // 選填
    date: "2026-08-28",            // 選填，用於排序
    tags: ["PG"]                   // 選填
  }
];
```

`url` 以 `http(s)://` 開頭時卡片標示「外部連結 ↗」並開新視窗。
手動項目的網址若與自動掃描到的相同會去重（以手動的為準）。

## 視覺風格

配色與 Cworld 一致：暖白底 `#f7f7f5`、白卡、邊框 `#e8e8e4`、16px 圓角、
`0 2px 12px rgba(0,0,0,.07)` 陰影（hover 換 `0 8px 32px rgba(0,0,0,.13)` 並上浮 3px）、
Helvetica Neue / PingFang TC 字族、海軍藍 `#2a3d5c` 導覽條與 `#2a3d5c → #3e6394` 漸層 hero、
遊戲卡的兩顆按鈕沿用 `#1a1a1a`／`#d32020`。固定亮色，沒有亮／深自動切換。

導覽條與 Cworld 一樣只出現在子頁（`all.html` 顯示「Omniplay / <分類>」麵包屑），
首頁沒有 — 否則會和 hero 的標題重複。

分類色（藍／紅／琥珀／綠）是這個站自己的一組，Cworld 沒有對應的分類色可以對齊。

報告類的卡片（競品分析、其他報告）底部顯示「更新 YYYY-MM-DD」：
競品分析取該資料夾的 `README.md` 的「報告日期」欄，其他報告取 `catalog.js` 的 `date`。
Demogame 用的是遊戲卡、常用連結用連結列，兩者都不顯示日期。

一般卡片刻意做小：欄寬下限 268px、內距 16px、圓角 12px，內容是
「分類標籤／標題／說明」＋（報告類才有的）日期，不放標籤列。
卡片上的代號只在**標題開頭不是它**時才顯示 —— Demogame 的標題本來就是
「H016 幸運王牌」，代號會重複所以自動隱藏；競品分析的廠商不在標題裡，照樣顯示。

favicon 是深藍 `#1b3a6b` 底白 J，字形幾何沿用 Cworld 那顆紅底 C
（64×64、`rx=14`、Helvetica Bold、`text-anchor:middle`），
`x/y` 依 Arial Bold 的實際字形範圍反推以視覺置中。因為它疊在海軍藍 hero 上
對比不足，hero 那顆 logo 加了 `box-shadow: 0 0 0 2px rgba(255,255,255,.32)` 描邊。
